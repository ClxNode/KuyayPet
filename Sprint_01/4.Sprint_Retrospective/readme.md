
# 4. Retrospectiva del Sprint

**Fecha prevista:** viernes 16 de octubre de 2026  
**Proyecto:** KuyayPet  
**Sprint:** Sprint 1 — Semana 9  
**Participantes previstos:** DevBrad, Dylan Quispe, IchiSieben, Joseph-L-Q, kevinesty, Gael Milla y Juan Vidal.

## ¿Qué salió bien?

- Se definieron tres historias de usuario prioritarias para el Sprint 1: HU-01 (registro de usuario), HU-02 (visualización de mascotas disponibles) y HU-03 (perfil de una mascota).
- Se identificaron los criterios de aceptación necesarios para orientar el desarrollo y las pruebas.
- Se propuso una distribución de responsabilidades entre los integrantes para organizar el trabajo.
- Se identificó la necesidad de preparar datos de prueba para validar la visualización de mascotas.

## ¿Qué fue difícil?

- Coordinar el acceso de todos los integrantes al repositorio de GitHub, especialmente de quienes tenían invitaciones pendientes.
- Organizar las dependencias entre la visualización de mascotas (HU-02) y el perfil detallado (HU-03).
- Determinar si el tiempo disponible era suficiente para completar las tres historias de usuario.
- Definir las pruebas necesarias para comprobar que cada historia cumpliera sus criterios de aceptación.

## ¿Qué aprendimos?

- Es importante definir los criterios de aceptación antes de comenzar el desarrollo.
- Las tareas deben distribuirse considerando la complejidad y el tiempo disponible.
- Las historias de usuario deben probarse antes de marcarlas como terminadas.
- Los datos de prueba deben identificarse claramente para no confundirlos con funcionalidades implementadas.

## Acción de mejora para el siguiente sprint

- **Acción:** Confirmar el acceso al repositorio al inicio del sprint y revisar diariamente el estado de las tareas y los bloqueos.
- **Responsable propuesto:** Juan Vidal, como coordinador del seguimiento, con la colaboración de todo el equipo.
- **Cómo verificaremos si funcionó:** Comprobar que todos los integrantes puedan acceder al repositorio, que las tareas tengan responsables y estados actualizados y que los bloqueos estén registrados.

> **Nota:** Esta retrospectiva es una propuesta basada en la planificación del Sprint 1. Debe validarse y ajustarse con las observaciones reales del equipo durante la reunión de cierre.

## Seguimiento de tareas

- **Pendiente:** la tarea todavía no se ha completado.
- **En proceso:** el responsable ha comenzado a trabajar en ella.
- **Hecho:** la tarea se completó y existe evidencia verificable.
- **Bloqueado:** existe un impedimento que evita continuar.

**Criterio de finalización:** una historia de usuario solo se marcará como terminada cuando cumpla sus criterios de aceptación y haya sido probada.
