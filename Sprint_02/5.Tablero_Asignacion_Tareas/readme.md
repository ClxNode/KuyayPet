## 5.3. Seguimiento del avance

El estado de cada tarea se actualizó en GitHub Project conforme al avance del Sprint 2.

| Estado | Descripción |
|---|---|
| Pendiente | La tarea todavía no ha comenzado. |
| En proceso | El responsable ha iniciado el desarrollo o la ejecución de la tarea. |
| Terminado | La tarea se completó y cuenta con evidencia verificable en `7.Pruebas`. |
| Bloqueado | Existe un impedimento que evita continuar con la tarea. El bloqueo debe comunicarse y registrarse en el Daily Scrum. |

## 5.4. Criterios de finalización

Una tarea se considerará terminada cuando:

- Se hayan completado las actividades descritas en el issue.
- Se hayan verificado los criterios de aceptación relacionados con la historia de usuario.
- Se hayan ejecutado las pruebas correspondientes.
- Se haya registrado la evidencia verificable en `7.Pruebas`.
- Se hayan integrado los cambios necesarios en el repositorio, cuando corresponda.
- Se haya actualizado el estado de la tarea en GitHub Project.

Una historia de usuario solo se marcará como terminada cuando cumpla sus criterios de aceptación, haya sido probada por su responsable y cuente con evidencia verificable.

La evidencia se almacenará en [`7.Pruebas`](../7.Pruebas/readme.md).

## 5.5. Acuerdos de seguimiento del equipo

Para mantener una adecuada organización durante el Sprint 2, el equipo acuerda:

- Asignar un responsable y una fecha límite a cada tarea durante la planificación.
- Mantener actualizados los estados de las tareas en GitHub Project.
- Comunicar oportunamente los bloqueos o dificultades que puedan afectar el avance.
- Registrar las pruebas y evidencias conforme se complete cada tarea.
- Revisar el cumplimiento de las tareas antes de finalizar el sprint.

## 5.6. Conclusión

El tablero de asignación de tareas permitió organizar el trabajo del Sprint 2, identificar las responsabilidades de cada integrante y realizar un seguimiento del avance de las historias de usuario.

Su actualización contribuye a mejorar la coordinación del equipo, facilitar la integración de los cambios y verificar el cumplimiento de los objetivos establecidos para el sprint.
