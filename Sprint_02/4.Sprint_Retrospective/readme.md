# 4. Sprint Retrospective — Sprint 2

**Proyecto:** KuyayPet  
**Sprint:** Sprint 2  
**Fecha de cierre:** 20 de noviembre de 2026

## 1. ¿Qué salió bien?

- Se avanzó en las funcionalidades del catálogo de mascotas, incluyendo el registro, la edición, las fotografías, los filtros y los favoritos.
- El equipo trabajó en tareas específicas y organizó los cambios mediante issues y Pull Requests.
- Se prepararon evidencias y se realizaron revisiones para comprobar el funcionamiento de las funcionalidades implementadas.

## 2. ¿Qué dificultades encontramos?

- Algunas funcionalidades requerían pruebas adicionales para verificar que cumplieran todos sus criterios de aceptación.
- Fue necesario coordinar la revisión y fusión de los Pull Requests para integrar los cambios.
- Algunas funcionalidades dependían de otras partes del sistema, por lo que fue importante considerar su integración.

## 3. ¿Qué podemos mejorar?

- Definir y distribuir las tareas con mayor claridad desde el inicio del sprint.
- Realizar las pruebas y registrar las evidencias conforme se completa cada historia de usuario.
- Revisar los Pull Requests oportunamente para facilitar la integración de los cambios.
- Verificar los criterios de aceptación antes de marcar una historia como terminada.

## 4. Compromisos para el siguiente sprint

- Mantener actualizados los issues y el tablero de tareas.
- Mejorar la coordinación entre los integrantes durante el desarrollo y la revisión del código.
- Completar las pruebas y evidencias correspondientes antes de cerrar las historias de usuario.
- Aplicar la Definition of Done acordada por el equipo para validar cada entrega.

## 5. Conclusión

El Sprint 2 permitió avanzar en las funcionalidades principales de KuyayPet relacionadas con el catálogo de mascotas. La retrospectiva permite identificar oportunidades para mejorar la coordinación, las pruebas y la integración del trabajo en los siguientes sprints.
