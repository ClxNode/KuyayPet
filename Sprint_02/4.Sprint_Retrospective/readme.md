# 4. Sprint Retrospective — Sprint 2

**Proyecto:** KuyayPet  
**Sprint:** Sprint 2  
**Fecha de cierre:** 20 de noviembre de 2026

## 1. ¿Qué salió bien?

- Se avanzó en el desarrollo de funcionalidades clave de KuyayPet relacionadas con el catálogo de mascotas, incluyendo el registro, la edición de información, la visualización de fotografías, los filtros de búsqueda y la gestión de favoritos.
- Se implementaron mejoras en la visualización de las interfaces, buscando que la información de las mascotas se presente de manera clara y organizada.
- Se desarrollaron y actualizaron historias de usuario, permitiendo organizar el trabajo en funcionalidades específicas y facilitar el seguimiento de los avances.
- El equipo utilizó issues y Pull Requests para gestionar los cambios realizados en el repositorio y mantener un mejor control del desarrollo.
- Se realizaron pruebas funcionales para verificar el comportamiento de las funcionalidades implementadas y comprobar el cumplimiento de los criterios de aceptación.
- Se generaron evidencias mediante capturas de pantalla que permiten demostrar el funcionamiento de las funcionalidades desarrolladas.
- Se realizaron revisiones de código y se integraron cambios mediante Pull Requests, favoreciendo la colaboración entre los integrantes.
- Se avanzó en la organización de las tareas del sprint y en el registro de las actividades realizadas por cada integrante.
- Se mejoró la coordinación del equipo durante el desarrollo, revisión e integración de las funcionalidades.

## 2. ¿Qué dificultades encontramos?

- Algunas historias de usuario requirieron pruebas adicionales para verificar el cumplimiento de todos sus criterios de aceptación.
- La revisión y fusión de los Pull Requests demandó coordinación entre los integrantes para evitar conflictos durante la integración.
- Algunas funcionalidades dependían de otros componentes del sistema, lo que dificultó realizar pruebas de manera independiente.
- Se presentaron actividades adicionales relacionadas con la corrección de errores y la validación de los cambios realizados.
- Fue necesario revisar las evidencias para asegurar que correspondieran con las funcionalidades implementadas.
- La coordinación de las tareas y la revisión de los avances requirió comunicación constante entre los integrantes.
- Algunas actividades necesitaron ajustes antes de poder considerarse completadas.

## 3. ¿Qué podemos mejorar?

- Definir con mayor claridad las tareas, responsabilidades y entregables de cada integrante al inicio del sprint.
- Establecer una mejor distribución del trabajo para evitar que algunas actividades se concentren al final del sprint.
- Realizar pruebas funcionales durante el desarrollo de cada historia de usuario, en lugar de dejar toda la validación para el cierre.
- Registrar las evidencias de las funcionalidades conforme se completen las pruebas.
- Revisar los Pull Requests de manera oportuna para facilitar la integración de los cambios.
- Mejorar la comunicación sobre los avances, dificultades y dependencias entre las tareas.
- Verificar que cada historia de usuario cumpla con sus criterios de aceptación antes de marcarla como terminada.
- Mantener actualizado el tablero de tareas para reflejar el estado real del trabajo.
- Fortalecer la revisión de código para detectar errores y posibles mejoras antes de integrar los cambios a la rama principal.

## 4. Compromisos para el siguiente sprint

- Mantener actualizados los issues, el tablero de tareas y el estado de las historias de usuario.
- Definir las responsabilidades de cada integrante antes de comenzar el desarrollo de las funcionalidades.
- Realizar un seguimiento continuo de las tareas para identificar posibles retrasos o dificultades.
- Registrar las evidencias de cada funcionalidad conforme se completen las pruebas.
- Realizar revisiones oportunas de los Pull Requests para facilitar la integración del código.
- Validar los criterios de aceptación antes de cerrar cada historia de usuario.
- Aplicar la Definition of Done acordada por el equipo para verificar que cada entrega cumpla con los requisitos establecidos.
- Mantener una comunicación constante entre los integrantes durante el desarrollo y la integración.
- Documentar los cambios realizados y las pruebas ejecutadas para facilitar el seguimiento del proyecto.
- Revisar los aprendizajes obtenidos durante el sprint para aplicarlos en la planificación del siguiente.

## 5. Conclusión

El Sprint 2 permitió avanzar en el desarrollo de funcionalidades importantes de KuyayPet, especialmente aquellas relacionadas con la gestión, búsqueda y visualización del catálogo de mascotas. Durante este sprint, el equipo trabajó en la implementación de historias de usuario, la realización de pruebas, la generación de evidencias y la integración de cambios mediante Pull Requests.

Asimismo, la retrospectiva permitió identificar oportunidades de mejora en la organización de las tareas, la coordinación entre los integrantes, la revisión del código y la validación de las funcionalidades.

Los aprendizajes obtenidos servirán como base para mejorar la planificación, fortalecer la colaboración y optimizar el proceso de desarrollo en los siguientes sprints, buscando entregar funcionalidades de mayor calidad y cumplir con los objetivos establecidos para el proyecto.
